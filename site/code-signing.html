How releases are made

Code signing policy

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

Status: Cloister’s application to the SignPath Foundation programme is in progress. Until it is approved, Windows releases are published unsigned; this page will name the first signed version.

What is signed

For every release, the Windows installer (Cloister_x.y.z_x64-setup.exe) and the Windows Installer package (Cloister_x.y.z_x64_en-US.msi) are signed with the SignPath Foundation certificate. Signing confirms that the file is an unmodified, automated build of the source code in github.com/Muntahi-Safwan/Cloister.

Releases are built only by GitHub Actions, on GitHub-hosted machines, from a version tag in that repository, using the release workflow. Each signing request is approved by hand before anything is signed.

The macOS and Linux downloads are not signed through SignPath. Every update package, on all three systems, also carries Cloister's own update signature, which installed copies check before installing anything.

Team and roles

Authors

  • Muntahi Safwan, owner of the repository. Authors may change the source code without further review.

Reviewers

  • Muntahi Safwan reviews every change from other contributors, including build scripts and workflows, before it is merged.

Approvers

  • Muntahi Safwan approves each signing request.

Everyone with these roles uses multi-factor authentication for GitHub and SignPath. The current list of people with write access is on the repository's contributors page.

Privacy policy

Apart from the update check and service icons described below, this program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

What Cloister connects to

  • The services you add. Cloister opens the websites you choose, such as WhatsApp Web or Gmail, each in its own private profile on your computer. They receive what they would in a web browser, and their own privacy policies apply.
  • Update checks. When it starts and every six hours, Cloister downloads a small file from github.com to see whether a new version exists. It sends nothing about you beyond what every web request carries (your IP address and the app's user agent). You can turn this off in Settings › About. GitHub's privacy statement applies.
  • Service icons. The service catalogue, and tiles set to show site icons, load icons from DuckDuckGo's icon service, which receives the address of the service (for example web.whatsapp.com) and nothing about you or your accounts. Tiles set to show initials do not load icons. DuckDuckGo's privacy policy applies.

What Cloister never does

  • No telemetry, analytics, crash reports, advertising or account.
  • Message text is never stored on disk or sent anywhere. Notifications are shown and then kept in memory only until Cloister closes.

Cloister shows web pages with the browser engine your system provides: Microsoft Edge WebView2 on Windows, and WebKit on macOS and Linux. Their makers' privacy statements apply to those engines.
